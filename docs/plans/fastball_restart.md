## 2. 核心障礙（未解問題摘要）

1. **從 7600 續訓必掉速**（最核心）。六次續跑 100–300 its 內 noisy 出手 17.65 → 16.0–17.1。存檔 / normalizer、出手步跳格、critic 不匹配都已排除；actor 相對變化 1e-4 就掉 1.4 m/s → 7600 的球速在刀鋒上。PPO 在 noisy 起始上的自然方向是「較慢較穩的手臂」，因為獎勵沒有付球速。整策略錨定（λ 1 / 1e4 / 1e5）守得住 identical、守不住 noisy → 不是訓練載具。
2. **球速項是否有效沒有乾淨證據**。1a / 1a' 都被漂移遮蔽。S1C 出手步付款設計（× 站穩、未出手 / 跌倒 = 0、16 m/s 以下 = 0）已確認不可鑽，從未跑過。
3. **η 是否可經現有手臂 / 手腕動作集訓練**未知。fb1b 效率坡只動了對照也有的量（0.21 → 0.25–0.30）。
4. **兩倍球速不是微調可達**，可能要回到規格層（手臂力矩、關節速度上限、投球參考動作）。
5. **打者相容性**：16300 只見過 55–75 km/h 來球。
6. 既知已接受：打者殘餘抖動、打者單 PA、P3c 聯合場景 11/64 跌倒（回歸檢查用）。

## 5. 路線 A：noisy 閘續訓 + 出手步球速項

### 5-1 設定（已實作，3c0f29a）

- Task：`AIB-Stage1dK70GW2MBASVRT1SYW110R5H5TW2PLW100P3CS1C-v0` = P3c 任務 + `w_stage_rel_speed` 100 × clip((v − 16) / 6, 0, 1)，與球項同付款條件、× 站穩、無高斯、無錨。
- 備援：`...P3CS1CW200-v0`（權重 200）。
- 規模：在 7600 表上 noisy 平均 5.6（45/128 有付、每顆 15.9），付款球 +1 m/s = +16.7。
- 訓練：從 7600、暖機 50 its / lr 1e-4、SEED 131、7600 → 8100；每 100 its identical 64 + noisy 128。

### 5-2 每段規則

| 時點 | 條件 | 動作 |
|---|---|---|
| 任何時點 | value loss > 405，或 noisy 站穩 < 40 連兩次 | 殺 |
| 7900（證偽） | noisy 出手中位 < 17.6（沒回到 base） | 殺，以 w200 重跑 7600 → 8100；再失敗即停並判「出手步球速項在此起點無效」 |
| 8100（段末） | noisy 出手 ≥ 17.95 且 noisy 站穩 ≥ 40 | PASS，下一段需新 GO |
| 每段之後 | noisy 出手中位較前段升 ≥ 0.3 m/s 且 noisy 站穩 ≥ 40/128 | 繼續下一段 |

T3 只回報不閘；32/128 是長期目標。依「falsifier = deterministic diag」規則，中途證偽看最新 ckpt 的表，不看訓練均值。

### 5-3 球速課程：坡的飽和點要跟著移

S1C 的坡 `clip((v − 16) / 6, 0, 1)` 在 22 m/s 飽和（`stage_env.py:687-690`），w200 只改權重不改飽和點。22 m/s 以上的球速不再加分，若不移坡，球速會停在 ~22 m/s，被誤判成規格瓶頸。

- **移坡條件**：某段末 noisy 出手中位 ≥ 坡上端 − 1 m/s（第一次 = 21 m/s）。
- **移法**：新坡 = (v_lo, v_lo + 6)，v_lo = 當前 noisy 出手中位 − 2 m/s；寬度固定 6 m/s、權重不變 → 付款球每 +1 m/s 的增益固定在 w / 6（w100 時 16.7），獎勵尺度不跳。下端上移後，原本有付的慢球會變 0，總獎勵平均會下降；這是預期的，不視為退步。
- **實作**：坡的上下端改成 cfg 欄位（現為常數），每次移坡是一個新 task id（`...P3CS1C_L<v_lo>-v0`），不改既有 S1C-v0 的行為。
- **移坡後評估**：新坡第一段開跑前，用上一段末 ckpt 在新 task 上跑 noisy 128 一次，記錄新項平均與有付顆數（對照 7600 的 5.6 / 45）；新段的 PASS 與證偽規則同 5-2，基準換成這張表。
- 進入第 5-4 節「規格瓶頸」判定的前提：坡上端 ≥ 當前 noisy 出手中位 + 2 m/s，也就是球速項仍有增益空間。

### 5-4 是否需要改規格（D2）

- 每段 +0.3 m/s 的速度下，17.65 → 33.3 m/s 需 ~52 段（~26000 its），不實際。
- **遙測工具**：`scripts/diag_arm.py`（不是 `eval_stage --arm_record`，後者只存 env 0 的動作，沒有力矩 / 速度）。它記錄投球手臂與腰關節在出手前 window_s 內每個物理子步的 SEA 馬達力矩是否達 `motor_effort`、馬達速度是否達 `motor_velocity`、關節速度對 `joint_vel_limits`、彈簧變形，以及出手附近的原始動作。用 `--envs 128`，噪聲設定與 noisy 128 表相同（`--set` 傳同一組 start noise）。
- **飽和比例**：每個關節 = 出手前視窗內「力矩在上限或馬達速度在上限」的子步比例，取 128 環境中位。對照 = 7600 基準（第 4 節第 7 步）。
- **工具需先擴充**（現版 `diag_arm.py:164-165` 把力矩與速度飽和分開累計，`:216` 輸出跨環境、跨視窗的平均，且只算出手視窗完整的環境）：
  - 每子步計算聯集 `sat_any = sat_t | sat_v`，逐環境、逐關節累計視窗內比例；
  - 輸出每關節：環境中位、四分位、有效環境數 n_valid / 128，另列 sat_t、sat_v 各自的中位供參考；
  - 缺失處理：未出手、出手前跌倒、或出手視窗不完整的環境排除並計數；n_valid < 96 時該表判「證據不足」，不做規格判定；
  - 舊輸出保留不變。擴充完成後才建立 7600 基準。
- **判定**：在 5-3 前提成立下，前兩段平均斜率 < 1 m/s / 段或球速平台化，而且肩 / 肘 / 腰至少一個主關節的飽和比例 ≥ 0.3、比 7600 基準高 → 判「瓶頸在規格層」，向使用者提 D2，附各關節飽和比例。0.3 是暫定值，第一次基準出來後若 7600 本身已 ≥ 0.3，改用「比基準高 0.15」。
- 飽和比例沒有升高，或 `diag_arm.py` 跑不出資料 → 判「證據不足」，不提改規格；改檢查獎勵（坡位置、付款顆數）與續訓漂移。
- 若斜率 ≥ 1 m/s / 段且站穩守住 → 繼續 A，在 M1（25 m/s）時做一次完整閘表 + 拍片確認動作沒有變形。

### 5-5 旋轉效率的排序

η 不在 A 的第一段裡加。理由：前次 fb1b 被漂移遮蔽，若同時加兩項無法分辨哪一項有效。A 拿到乾淨的球速斜率後，再加效率坡項（80bda54，r_spin = 30 · clip((η − 0.21)/0.64, 0, 1) · [|tilt| ≤ 45°] · [rpm ≥ 400]）作為獨立一段，證偽 = 該段末 noisy η 中位 ≥ 0.45 或 noisy tilt+eff ok ≥ 40/128。
