### 5-2 每段規則

判定單位改為 **launch**（使用者 11-07 同意「判定點多次抽樣」的方向；經 Codex 討論定案）：一次 launch = 一次 `eval_stage` noisy 128（`start_joint_noise=0.02 start_noise_ramp_steps=0`），統計量 = 該次已出手球的出手中位。**判定量 = 各 launch 中位的平均**（不是所有球合併後的中位）。launch 設定固定，128 與 256 不混用。每次 launch 保存 release csv（檔名即 launch ID）。

**基準**：P3c 7600 的 7 次 noisy 128 launch（第 4 節第 6 步），k_b = 7、平均 17.22、sd 0.27。之後的段，基準換成前一段段末 ckpt 的全部判定 launch。

**差值檢定**（`scripts/median_delta.py`）：Δ = mean(候選) − mean(基準)，SE = √(s_c²/k_c + s_b²/k_b)，Welch t（Welch–Satterthwaite 自由度）90% 雙尾區間 [lo, hi]。Welch 假設各 launch 中位近似常態、彼此獨立；k 小時區間偏寬，是保守方向。−0.05（容忍）與 +0.3（目標）是固定的實務門檻，不因量到的 sd 移動；sd 只決定需要幾次 launch。

**每個判定點（7900、8100）的流程**：首批 k_c = 4 次 launch（train_live 該點自己的 1 次 + 鏈補 3 次，等 Isaac < 2 才起）→ 未定時補 4 次（同一 ckpt，k_c = 8）→ 依下表最終處置。補樣上限一次，不抽到過為止。k_c = 4 的理由：s = 0.27 時 SE ≈ √(0.27²/4 + 0.27²/7) = 0.17，PASS 需要 Δ > t·SE ≈ 0.31，與 +0.3 目標同量級。

| 時點 | 判退步 / FAIL | 判通過 | 其餘 = 未定 |
|---|---|---|---|
| 每 100 its（監看） | 單次 noisy 128 站穩 < 40/128 連兩次 → 殺 | — | — |
| 任何時點 | value loss 1–5 平均 > 405 → 殺 | — | — |
| 7900（證偽） | hi < −0.05：有退步證據 → 殺，以 w200 重跑 7600 → 8100；w200 再判退步即停，結論「出手步球速項在此起點無效」 | lo ≥ −0.05 → 沒退步 | 補樣後仍未定 → 不殺，繼續到 8100（證偽需要證據才成立） |
| 8100（段末） | Δ < 0.3 且 hi < 0.3 → FAIL | Δ ≥ 0.3 且 lo > 0 且候選 launch 平均站穩 ≥ 31.25%（40/128）→ PASS，下一段需新 GO | 補樣後仍未定 → 判 FAIL，摘要標「未定」，連同 Δ、區間、各 launch 中位回報 |
| 每段之後 | 同 8100，基準換成前一段段末 launch | 同 8100 | 同 8100 |

PASS 與 FAIL 互斥（PASS 要 Δ ≥ 0.3，FAIL 要 Δ < 0.3）。PASS 的意思是「確認有改善（lo > 0）且點估計達 +0.3」，不是「確認改善至少 0.3」。

**特性（診斷，非校準標準）**：7 次 7600 launch 分成基準 3 / 候選 4 的 35 種組合，falsifier 判 REGRESS 0 次，segment 判 PASS 1 次。模擬（基準 = 這 7 次，候選 4 次 ~ N(μ + 位移, 0.27)，4000 次）：位移 0 → 誤判 REGRESS 1.0%、誤判 PASS 0.9%；−0.4 → REGRESS 59%；+0.3 → PASS 40%（其餘多為未定，補樣後再判）；+0.5 → PASS 84%。過去六次續跑的漂移是 −1.2 到 −1.7 m/s，遠在可偵測範圍內。方法鎖定後，以之後新的 launch 驗證，不再依這批資料調參。

**實作與驗證**：`scripts/median_delta.py` 已改為 launch 版（輸入基準 / 候選 csv 列表，每個 csv 一次 launch）。鏈的 judge 在 7900 / 8100 改為：收齊 4 次 launch → 呼叫 median_delta → 未定則補 4 次再呼叫 → 處置。起跑前用既有 7 次 csv 跑一次鏈的 judge 函式（乾跑，不訓練），確認讀檔、呼叫與處置分支正確。

**驗收閘的獨立確認（D6，新增，需使用者同意）**：M1 / M2 / M3 每張表維持使用者規格的 noisy 128 與原門檻。但同一條訓練線反覆評估，挑出一次過閘的表，會增加偶然通過的機會；M3 又直接決定能否替換 P3c。提案：候選 ckpt 固定後，另抽兩批全新的 noisy 128，兩批都要各自過閘才算通過；任一批不過，該 ckpt 判「未通過」，繼續訓練，不再對同一 ckpt 重抽。挑選候選用的那張表不算在這兩批裡。D6 未決之前，任何單表過閘都不能完成 M3 採用（P3c 不被替換），只能回報。

### 5-3 球速課程：坡的飽和點要跟著移

S1C 的坡 `clip((v − 16) / 6, 0, 1)` 在 22 m/s 飽和（`stage_env.py:687-690`），w200 只改權重不改飽和點。22 m/s 以上的球速不再加分，若不移坡，球速會停在 ~22 m/s，被誤判成規格瓶頸。

- **移坡條件**：某段末 noisy 出手中位 ≥ 坡上端 − 1 m/s（第一次 = 21 m/s）。
- **移法**：新坡 = (v_lo, v_lo + 6)，v_lo = 當前 noisy 出手中位 − 2 m/s；寬度固定 6 m/s、權重不變 → 付款球每 +1 m/s 的增益固定在 w / 6（w100 時 16.7），獎勵尺度不跳。下端上移後，原本有付的慢球會變 0，總獎勵平均會下降；這是預期的，不視為退步。
- **實作**：坡的上下端改成 cfg 欄位（現為常數），每次移坡是一個新 task id（`...P3CS1C_L<v_lo>-v0`），不改既有 S1C-v0 的行為。
- **移坡後評估**：新坡第一段開跑前，用上一段末 ckpt 在新 task 上跑 4 次 noisy 128 launch，記錄新項平均與有付顆數（對照 7600 的 5.6 / 45）；新段的 PASS 與證偽規則同 5-2，基準換成這張表。
- 進入第 5-4 節「規格瓶頸」判定的前提：坡上端 ≥ 當前 noisy 出手中位 + 2 m/s，也就是球速項仍有增益空間。

### 5-4 是否需要改規格（D2）

- 每段 +0.3 m/s 的速度下，17.65 → 33.3 m/s 需 ~52 段（~26000 its），不實際。
- **遙測工具**：`scripts/diag_arm.py`（不是 `eval_stage --arm_record`，後者只存 env 0 的動作，沒有力矩 / 速度）。它記錄投球手臂與腰關節在出手前 window_s 內每個物理子步的 SEA 馬達力矩是否達 `motor_effort`、馬達速度是否達 `motor_velocity`、關節速度對 `joint_vel_limits`、彈簧變形，以及出手附近的原始動作。用 `--envs 128`，噪聲設定與 noisy 128 表相同（`--set` 傳同一組 start noise）。
- **飽和比例**：每個關節 = 出手前視窗內「力矩在上限或馬達速度在上限」的子步比例，取 128 環境中位。對照 = 7600 基準（第 4 節第 7 步）。
- **工具需先擴充**（現版 `diag_arm.py:164-165` 把力矩與速度飽和分開累計，`:216` 輸出跨環境、跨視窗的平均，且只算出手視窗完整的環境）：
  - 每子步計算聯集 `sat_any = sat_t | sat_v`，逐環境、逐關節累計視窗內比例；
  - 輸出每關節：環境中位、四分位、有效環境數 n_valid / 128，另列 sat_t、sat_v 各自的中位供參考；
  - 缺失處理：未出手、出手前跌倒、或出手視窗不完整的環境排除並計數；n_valid < 96 時該表判「證據不足」，不做規格判定；

- **判定**：在 5-3 前提成立下，前兩段平均斜率 < 1 m/s / 段或球速平台化，而且肩 / 肘 / 腰至少一個主關節的飽和比例 ≥ 0.3、比 7600 基準高 → 判「瓶頸在規格層」，向使用者提 D2，附各關節飽和比例。0.3 是暫定值，第一次基準出來後若 7600 本身已 ≥ 0.3，改用「比基準高 0.15」。
- **7600 基準結果（11-07，noisy 128，n_valid 128/128）**：肩 3 軸、肘、手腕 roll 0.000；手腕 pitch 0.18、yaw 0.11；腰 yaw 0.41、pitch 0.37（全是力矩）。依上一條，腰的門檻改為「基準 + 0.15」（yaw 0.56、pitch 0.52），肩 / 肘維持 0.3。
- 飽和比例沒有升高，或 `diag_arm.py` 跑不出資料 → 判「證據不足」，不提改規格；改檢查獎勵（坡位置、付款顆數）與續訓漂移。
- 若斜率 ≥ 1 m/s / 段且站穩守住 → 繼續 A，在 M1（25 m/s）時做一次完整閘表 + 拍片確認動作沒有變形。

### 5-5 旋轉效率的排序

η 不在 A 的第一段裡加。理由：前次 fb1b 被漂移遮蔽，若同時加兩項無法分辨哪一項有效。A 拿到乾淨的球速斜率後，再加效率坡項（80bda54，r_spin = 30 · clip((η − 0.21)/0.64, 0, 1) · [|tilt| ≤ 45°] · [rpm ≥ 400]）作為獨立一段，證偽 = 該段末 noisy η 中位 ≥ 0.45 或 noisy tilt+eff ok ≥ 40/128。

**已查到的訓練事實（tensorboard 與 ckpt，CPU）**：

**下一步 = 診斷，不起訓練**（CPU 或短 GPU 診斷，訓練需使用者核准）：
1. 分項回報：用 7600 在 S1C 任務上跑一次短 rollout（無更新），記錄球速項、球項、站穩相關各項每 episode 的平均與有付顆數。看球速項佔總回報的比例。

   - KL 集中在少數極小 std 欄 → 候選 = 欄 std 下限或排除這些欄的 KL；
   - 球速項佔比太小 → 候選 = w200 或重新定標；
   - 兩者都不是 → 候選 = 第 6 節 B（需先寫出可驗證假說）。

- 必須先寫出可驗證假說，例如「整策略錨限制了下肢補償，noisy 起始的站穩需要腿 / 軀幹偏離 7600」，並附支持它的診斷。

- 守住但段末未增速時，只結論「本次受約束續訓未取得增速」，不排他地歸因於優化。

### 5-7 診斷結果（11-07 22:5x）與設計提案 S1D（待 Codex）

診斷 run `fbdiag`：從 7600、S1C 任務、與 fb1cl100 相同設定（SEED 131、critic 暖機 50、LR_FLOOR 3e-7），共 60 次更新，不存 ckpt。資料在 `logs/fb1c/diag_update.jsonl` 與 `logs/fb1c/diag_train.txt`；hook 見 f9db4f1（預設關閉）。

**分項回報**（暖機 50 次 rollout、16101 局的每局平均）：

| 項目 | 每局平均 |
|---|---|
| 總計 | 12.5 |
| 存活 + 姿態品質 | 87.3 |
| 跨步 | 53.5 |
| 跌倒 / 掉球 | −132.7 |
| 球項合計 | 4.38 |
| 其中球速項 | 0.57 |

- 有付款的局占 5.2%，球速項有付的占 3.0%。
- 球速項約佔回報絕對量的 0.2%，比跌倒項的變異小兩個數量級。

**一次更新的解剖**（更新 7650–7659，每次都一樣）：
- approx KL 0.023–0.029。其中欄 2（waist_yaw，std 0.0003）佔 85–92%，欄 4（r_hip_roll，std 0.0010）佔 7–12%；其餘 27 欄合計 < 3%。
- |Δμ| / σ：欄 2 約 0.16，其餘欄約 0.01。
- 關節名依機器人關節順序（`l_hip_yaw, r_hip_yaw, waist_yaw, l_hip_roll, r_hip_roll, …`，取自既有 log 印出的順序）。
- 去掉這兩欄，更新後 KL ≈ 5e-4，低於 desired_kl / 2 = 1.5e-3。判讀：兩欄主導更新後 KL，**疑似**限制了 adaptive scheduler（scheduler 看的是更新過程中各 mini-batch 的 KL，不完全等於更新後 KL；S1D 會直接記錄 scheduler 的決策）。
- 每次更新在自己那批資料上的 surrogate 增益都是正的（+2e-3 到 +6e-3）。更新確實朝 surrogate 走，但淨效果沒有累積成改善。

**TF32 A/B**（7650，同一狀態）：
- KL：TF32 開 0.024、關 0.060。
- actor 相對變化：開 1.4e-5、關 2.3e-5。
- 兩個結果之間的差：1.7e-5，與更新本身同量級。
- 判讀：在 σ = 3e-4 的欄位上，log-prob 的梯度（∝ 1/σ²）對數值誤差很敏感。這是觀察到的現象，不另作歸因。

**判讀**：
- waist_yaw 是腰部的主要出手關節（第 5-4 節飽和基準：腰 yaw 力矩飽和 0.41，全身最高），但它在 7600 幾乎是確定性輸出，PPO 在這欄沒有探索。
- 同一欄又把 KL 撐到目標的 8 倍，讓其他 27 欄只能用下限學習率移動。
- 這解釋了「學習率在下限、KL 仍超標」。但它不解釋漂移本身，也不保證放開後會增速。

**提案 S1D（一次只改一件事）**：
- **改動**：S1C w100 不變，只加既有的 `--min_noise_std 0.005`（train_live 的 `MIN_NOISE=0.005`）。它是策略動作空間的全域下限：目前只碰到 std 低於它的欄 2（0.0003）與欄 4（0.0010），下一個最小的欄是 0.0085；之後若其他欄降到 0.005 以下也會被 clamp（每次更新記錄 std，可查）。程式不用改。
- **換算成關節角**（`pitch_env.py:482`：目標角 = 參考 + 動作 × action_scale × residual scale；本任務 residual_scale 0.5、arm 0.25、腿在 0.5 s 後 × free_leg_gain 2.0）：waist_yaw 每單位動作 1.0 × 0.5 = 0.5 rad → std 0.0003 → 0.00015 rad，下限 0.005 → 0.0025 rad（0.14°）；r_hip_roll 0.5 × 0.5 = 0.25（0.5 s 後 0.5）rad → 0.001 → 0.00025–0.0005 rad，下限 → 0.00125–0.0025 rad。其他欄 std 0.0085–0.043，換算多在 0.002–0.02 rad。下限把兩欄的雜訊拉到與其他欄同量級，沒有超出。
- **起跑前的無更新 rollout**（R10）：凍結 7600（critic 暖機期 actor 不更新），std 下限 0.005，SEED 131，40 次 rollout，對照 fbdiag 前 40 次暖機 rollout（原 std、同種子）。比較 success_set、fall_rate_set、drop_rate_set、每局付款率、分項回報。**預定處置**：success_set 絕對下降 > 0.03，或每局付款率相對下降 > 20% → 0.005 不採用，改 0.002 再做一次同樣的 rollout；0.002 也不過 → S1D 不起跑，回報。
- **無更新 rollout 結果**（11-07 23:1x，`fbstd005`，`logs/fb1c/diag_std005.jsonl`，第 7639 次 rollout 的 EMA 與 40 次 rollout 的每局分項）：

| | 原 std（fbdiag 暖機） | 下限 0.005（fbstd005） |
|---|---|---|
| success_set | 0.160 | 0.143（−0.017） |
| fall_rate_set | 0.684 | 0.732 |
| drop_rate_set | 0.110 | 0.094 |
| success_rsi | 0.420 | 0.444 |
| 每局付款率 | 0.039 | 0.039（0%） |
| 每局球速項 | 0.449 | 0.412 |
| 每局總回報 | 16.58 | 16.51 |
| 局數 | 10705 | 10737 |

  依預定處置：success_set 下降 0.017 < 0.03，付款率不變 → **0.005 採用**。fall_rate_set +0.048 只回報（EMA 值，未設門檻）。
- **預期機制**：
  - 欄 2 / 4 的 KL 貢獻下降（固定 Δμ 時降 25–280 倍，但 std 同時改變採樣與梯度，實際倍數待量），adaptive 學習率可以離開下限。
  - waist_yaw 重新有探索。
- **起跑**：從 7600、SEED 131、critic 暖機 50、7600 → 8100。
- **規則**：沿用 5-2（launch 判定、每 100 its 監看站穩、value loss）。
- **機制證偽**（不需要 launch，看第 11–20 次 actor 更新，即 7661–7670）：
  - DIAG_JSON 開著，每次更新記錄總 KL、各欄絕對 KL、更新後學習率、scheduler 的降 / 升次數（每次更新 20 個 mini-batch 決策）。
  - 成立 = 三項同時：(1) 10 次中 ≥ 8 次更新後學習率 > 1e-6（下限的 3.3 倍，視為持續離開下限）；(2) 欄 2 絕對 KL 的中位 ≤ 1.5e-3；(3) 總 KL 中位 ≤ 0.025（不比 S1C 差，排除其他欄 KL 暴增）。欄 2 的佔比只作輔助。
  - 不成立 → 殺掉，結論限於「0.005 在本次預算內未解除限制」，不概括成 std 下限無效。
- **風險**：
  - 學習率上升後，每次更新變大，漂移可能更快。這會由 7900 證偽與站穩監看擋下。
  - 訓練 rollout 在 waist_yaw 上多了約 0.0025 rad 的探索雜訊。評估用 μ，不直接採樣這項雜訊，但訓練後的 μ 仍會因此改變；站穩風險由起跑前的無更新 rollout 與每 100 its 監看把關。
- **不在 S1D 裡一起改**：
  - 球速項的佔比（0.2%）與 RSI 局的跌倒變異。這是下一個候選（重新定標或只對 set 起始付款）。
  - 等 S1D 結果再分開提，Codex 先審。
- **成功後**：S1D 的 PASS 規則同 5-2；8100 PASS 才進下一段。
